# Motion selection: purpose first

Choose the *communication problem*, then the technique. Query: `python -m contentos.intelligence.catalogue query --purpose <p> [--content-type <t>] [--aspect 9:16]`.

| Viewer must grasp | Purpose | Typical techniques (see catalogue for the ranked list) |
|---|---|---|
| how parts connect | relationship / structure | constellation-hub, center-outward-expansion, control-target-sync |
| the order of steps | sequence | svg-path-draw, typewriter-reveal, spatial-pan-stations |
| how two things differ | difference | comparison-split, split-tilt-cards, scale-swap-transition |
| a number or trend | quantity | dataviz-countup, stat-bars-and-fills, chart-scrub-readout |
| what an interaction looks like | demonstration | cursor-ui-demo, prompt-type-submit-generate, real UI footage when the interaction itself is the point |
| the one thing to remember | emphasis | kinetic-beat-slam, asr-keyword-glow (emphasis, not explanation) |
| mood or place | mood | ambient-glow-bloom (atmosphere only, never carries information) |

Rules that outrank taste: (1) run the simpler-alternative test: could a held frame or plain text teach this? Animate only when change over time is the point. (2) one primary motion per scene. (3) Accessibility notes in the catalogue (flicker, fast motion) apply. (4) A technique with confidence `unverified` is usable but not "proven": say so in the decision record. (5) Seeded purposes are a first draft by heuristic; if a technique does not do what its tag says in your composition, record that as evidence (`evolution.md`), do not bend the composition.
