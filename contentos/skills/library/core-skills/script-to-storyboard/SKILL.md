# Script to Storyboard

## Workflow
1. Read the script and identify audience, objective, hook, key claims, narrative beats, examples, payoff, and CTA.
2. Flag claims that need sources; do not invent facts, commands, metrics, or demonstrations.
3. Classify each segment by intent: hook, concept, mechanism, comparison, code demo, architecture, example, evidence, summary, or CTA.
4. Read the style registry, skill map, and live capability registry.
5. Recommend a primary visual style and two meaningfully different alternatives if useful.
6. Map each scene to a visual metaphor, layout, motion technique, duration, caption treatment, and audio cue where relevant.
7. Identify skill dependencies, unsupported effects, asset rights questions, and uncertainty.
8. Return the storyboard and rationale. Do not render until the appropriate approval gate is satisfied.

## Acceptance criteria
The storyboard explains why each visual improves comprehension, preserves technical accuracy, avoids repetitive composition, and can be implemented with the existing factory or explicitly identifies a gap.
