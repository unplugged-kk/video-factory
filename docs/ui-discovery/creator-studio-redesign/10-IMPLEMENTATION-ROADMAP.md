R0 safety boundary: serve a standalone static fixture prototype on a separate origin without a reverse proxy, production credentials, real client module, production media endpoints or hidden action handlers. Use local fixture assets and an in-memory adapter only; enforce `connect-src 'none'` and `form-action 'none'`, prohibit external navigations and embeds, and test with production server stopped. Browser tests fail on any attempted network request outside the static fixture allowlist, including reads of `/api/v1`, and exercise every simulated mutation. Label approve, submit, retry and export as simulated; reset fixture state on reload. Include invalid, blocked, duplicate, running and stale-capability rows and one readiness change between validate/submit. Test keyboard, focus return, mobile reflow and both themes in the isolated prototype, not against production.

R0 contains no R1 adapter, dev proxy or live-mode flag. R0 acceptance cannot authorize R1, later phases or production work. Neither R0 nor R1 requires backend expansion to be planned. Restrict mutation routes to the explicit contract and owner-approved integrity policy. Quality bar: no critical axe violations, complete manual keyboard flow and focus checks, media controls/transcript where applicable, parity smoke on old routes, and no regressions in approval, export or worker tests. Use contained test workspaces only once implementation is authorized. Record actual outcomes and report rendering tests separately from fixture UI acceptance. Promote capability labels only from recorded evidence.

**Assumptions:** main milestones ship via independently reviewable PRs, no new dependency without an ADR. **Open questions:** prototype operator test participants/fixtures, production release order and whether creative verdict blocks export.
