# R0 execution specification: isolated Cutting Room prototype

**Research date:** 2026-11-24. **Scope:** execution plan only; implementation is not authorized. **Evidence and sources:** [Review 02 dispositions](DECISION-LOG.md#review-02-dispositions), [capability baseline](00-RECONCILIATION.md), [responsive wireframes](05-SCREEN-SPECIFICATIONS.md), [visual system](06-VISUAL-DESIGN-SYSTEM.md). **Verified findings:** the live Studio has an actual API client; a standalone fixture experience must not import it. No prototype exists or has been tested by this document.

## Scope and non-goals

If separately authorized, use vanilla ES modules, CSS and semantic HTML to test operator orientation and creative workflow, not throughput or engine behavior. A persistent `Prototype · synthetic data` indicator appears on every route. Label all state-changing controls `Simulate …`; simulation changes memory only and resets on reload or explicit Reset. No production jobs, approvals, exports, downloads of output, publishing, renderer invocation, media picker/upload, file writes, database, auth, worker control, generated production media or agents. No R1 read-only adapter, even as an optional build mode. Rendered evidence is simulated, not qualification for the production system.

## Isolation contract

- Use a dedicated static fixture root, served on a distinct loopback origin with a non-conflicting port and no proxy, backend or fallback to the live app. The server maps exact allowlisted static paths; no directory indexing, arbitrary file resolution, symlinks, parent directory, source tree, home, workspace or storage mounts. No server-side execution triggered by requests. Use only explicit GET/HEAD static serving, no live app server process. Do not read environment credentials or ship a client token. Origin capability is not enough: production endpoints are absent from the build and server.
- Serve headers including `Content-Security-Policy: default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self'; media-src 'self'; font-src 'self'; connect-src 'none'; form-action 'none'; frame-src 'none'; frame-ancestors 'none'; object-src 'none'; worker-src 'none'; base-uri 'none'` and `Referrer-Policy: no-referrer`. No inline script/style exceptions. No third-party fonts, scripts, analytics or assets; local system fonts and original sample illustrations only. No iframes/embeds, outbound hyperlinks, window opens, service workers, forms with submission semantics, speculative resource hints or redirects.
- Use static relative fixture resources and an in-memory adapter with synchronous transitions or deterministic test-controlled clock. Do not include a network client, production route constants or filesystem bridge. No cookie, local storage, IndexedDB or persistence path. Hash routes only; unknown routes show fixture Not found with Home action, never perform a navigation outside the static origin. CSP is defense in depth, not a substitute for rejecting outgoing navigation and verifying code/asset boundaries.

## Fixtures and components

Use deterministic IDs in a `fixture-` namespace. State shape: `capabilities[id,state,observedAt,evidence]`; `assets[id,fixtureDigest,kind,rights,availability]`; `jobs[id,format,language,track,specRevision,pinnedAssets,execution,qa,creative,exportEligibility,attempts]`; `subjects[jobId,gate,revision,fixtureDigest,content]`; `batches[id,revision,rows,receipt]`; `campaigns[id,defaultsRevisions,episodes,resolvedFields]`; `activity[id,jobId,type,observedAt,fixtureActor,receipt]`. Digests are illustrative IDs, not cryptographic attestations. No valid grants or real artifact paths ever appear. Human labels say `Simulated local operator`, not authenticated user.

- Independent batch `fixture-b20`: 20 distinct topics (e.g. nearest-neighbor map, equal loss/gain, canal locks, monsoon vocabulary, podcast recap), with 12 ready, 3 invalid, 2 blocked, 1 duplicate, 1 stale, 1 already running. Include English Shorts, Hindi/English long-form, manual Track B and unsupported lyric workflows. After validation, make one ready row lose its mocked voice runtime without altering its spec.
- Campaign `fixture-canals`: 20 episode records, at least three representative states. Pin episode 01 to `r2` and show why `r3` does not change it. Episode 04 overrides language; another explicitly clears required voice and fails validation. New logo pins a different fixture digest; one unavailable old asset blocks its dependent draft without substitution.
- Review fixtures: exact script and composition subjects plus a changed-then-restored revision fixture; one QA pass/creative changes requested and one QA fail/creative accepted; export eligibility remains independent. Use local vector posters and a scrub-able frame/storyboard preview with transcript; no requirement to generate video. Agent activity uses fixed handoff/return/error receipts, not typing animation, autonomous execution or live telemetry.
- Reusable blocks: shell, media poster and figure caption, capability badge with evidence popover, status chip, filter bar, row selection table/cards, readable stage list, activity list, resolved-value comparison, progress summary from counted rows, route-local drawer, accessible dialog, labeled form controls, change diff, empty/error/cached states and receipt panel. Use semantic tables on wide views and labeled field/value rows on mobile.

## Journeys and interaction rules

1. **Create:** choose a target and fixture source, see plan and blockers, correct a field, simulate validate/save, open job. Switch between ready Shorts and conditional long-form examples. No simulated submission of blocked or topic-only draft without a complete synthetic spec.
2. **Batch:** choose intake, validate 20, resolve one field error and select ready subset. Show exact selected scope. Simulate submit with partial drift; duplicate action replays the same session receipt, never increases count. Simulate an interrupted response, recover receipt from in-memory intent state, retry only previously unaccepted rows after revalidation. It is not evidence of durable batch implementation.
3. **Campaign:** inspect inherited/overridden/defaulted/cleared values; preview explicit rebase for one selected draft. Cancel retains revision; confirm produces draft lineage, never edits prior pins, history or reviewed jobs. Compare old/new fixture asset IDs and show missing-asset remedy rather than substituting.
4. **Review and export:** open exact subject from inbox, inspect version/diff/evidence, then simulate grant. Advance fixture revision while dialog is open; disable rather than silently swap subject. For technically eligible fixture with creative Changes requested show advisory, not a blocker. Simulate independent export receipts (eligible, failed and skipped) without file I/O, and no Publish action.
5. **Recovery:** inspect failed attempt, read sample error, preview invalidation scope, simulate retry; same job, new attempt, previous receipt retained. Running/locked rows disable retry and explain why. Show last observed, unknown and disconnected states via fixture controls; no backend poll, network use or speculative ETA.

## Visual and responsive contract

Adopt Cutting Room as test direction only: real hierarchy through original poster illustrations and lavender accents, one dominant action, warm focus ring, matte surfaces rather than KPI cards or shader accents. Use dark canvas/panel/text/accent `#141320 / #1D1C2B / #F6F1FF / #D7BBFF`; light `#F4F2F9 / #FFFFFF / #221D31 / #5426A1`. Use system sans with Indic fallback, monospace IDs, 4/8/12/16/24/32/48 spacing, semantic warning/error/focus tokens and layouts from [06](06-VISUAL-DESIGN-SYSTEM.md). Motion communicates selection, drawer or subject change: 100 ms hover, 160 ms selection, ≤220 ms drawer; reduced motion removes translations and shimmer; never animate readiness changes as simulated activity. No autoplay, gratuitous gradient or rearrangement while typing.

At ≥1200 px use rail/primary pane/evidence column where needed; 768–1199 uses compact rail and evidence drawer; <768 uses one column, preserved route context and accessible action tray that never hides focus. At 320 px, wrap difficult labels and offer structured row detail instead of page-wide overflow. Keep text/status readable without color or tooltip. Visible persistent focus, skip link, heading focus on route change, Escape and focus return for modal/drawer, keyboard-accessible selection/filter and inputs, captions/transcript/static alternative for time-based fixtures. Compare Cutting Room with Precision Workbench using task success, wrong actions and blocker interpretation on equivalent **fixture** tasks; no connection to live Studio for comparison.

## Browser and manual validation

| Check | Required evidence after authorization |
|---|---|
| Isolation / network | In a fresh browser context with service workers blocked, collect request attempts, CSP violations, redirects, navigations and popups. Allow only exact fixture origin plus allowlisted methods/paths; fail and abort any other request, including GET `/api/v1`, credential/media paths, WebSockets or remote hosts. Also fail on application CSP violations (blocked attempts can occur before a request event). Assert expected CSP. Run with the production server stopped; if it is already running, defer the test rather than stopping an operator process. The harness must not start or probe the production server over HTTP. Repeat checks across all destinations and simulated actions, including reset. |
| Isolation negative controls | Separately exercise assertion wiring with a harness-controlled blocked non-fixture target; intercept and abort locally without contacting a live service. Verify non-allowlisted static path and unsupported method refused, source/fixture inventory contains no production imports or private media, links/popups remain fixture-local, and storage remains empty after journeys. |
| Behavior | Deterministic tests for all five journeys, addressable context routes, state axes, receipt replay, campaign rebase and stale confirmation refusal; check that reset removes all simulated changes. No evidence claim beyond the fixture. |
| Responsive and accessibility | Browser fixture widths 1440, 1024, 390 and 320 CSS px; light/dark, reduced motion, forced colors, zoom/manual 200%, keyboard only, focus return and no obscured focus, screen-reader pass and Indic strings. Verify actual foreground/background ratios (4.5:1 normal text, 3:1 large text and applicable controls). Use existing available fixture tooling only after authorization; flag any missing tooling, do not silently skip evidence. |
| Product quality | Operator independently identifies the next blocker, submits the intended ready subset, explains why the pinned episode did not change, distinguishes artistic verdict from export eligibility, and explains that no action is real. Record task completion, errors and qualitative feedback; no invented metric thresholds or adoption claims. |

**Acceptance:** all routes and context journeys match the fixture contract; zero non-fixture attempts during normal scenarios; negative controls detect attempts without live contact; responsive/accessibility checks recorded per theme; no application/config/production data touch; owner reviews the visual/workflow evidence before authorizing any follow-up. Report exact commands, environment, failures, skips and screenshots if produced outside production. Passing R0 cannot prove R3 approval, R4 durability or asset probing.

**Assumptions:** a standalone local static host and existing browser tooling can be used after permission. **Open questions:** owner authorization and style/stack proposals, location of future standalone fixture root, prototype evaluator and equivalent comparison fixtures.
