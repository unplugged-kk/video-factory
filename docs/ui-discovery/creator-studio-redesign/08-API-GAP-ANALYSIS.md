# 08 / API gaps and contracts

**Research date:** 2026-11-24. **Scope:** existing versus candidate server operations. **Evidence / sources:** `contentos/ui_api.py:dispatch`, `contentos/ui_api.py:write_authorized`, `contentos/ui/api.js`, `contentos/ui_state.py`, `contentos/dashboard.py`, `tests/test_ui_api.py`, [approval policy](../../audit/APPROVAL_POLICY.md). **Verified:** token and local Host/origin checks, spec collision, lock conflict, stale digest and bounded log/media have test coverage. Session token is not multi-user authentication.

| Operation | Current `/api/v1` routes | Gap / recommended implementation contract |
|---|---|---|
| Readiness and planning | `GET /health[?refresh=1]`, `/capabilities` | Proposed `POST /plans/validate` with `{intent,inputs,target,options}` → version, ordered capabilities, input issues and manual steps. No side effects, billable generation or readiness inferred from registry existence. |
| Author and execute | `GET /jobs`, `/jobs/:id`; `POST /specs/validate`, `/specs`, `/jobs/:id/run` | Preserve validate/create distinction. Proposed draft revisions with conditional compare; never rewrite an approved file. Keep `ALREADY_RUNNING` distinct from accepted new work. |
| Observe and recover | job `/events`, `/stages/:stage/log`, `GET/POST /rerun`, `POST /qa`, `GET/POST /queue`, `POST /queue/:id/requeue` | Reread after events, report actual queue transitions, bounded logs. No worker start, cancel or fleet management added. |
| Manual Track B | `POST /jobs/:id/track-b/:action` | Do not treat plan artifact as renderer approval. Expose only actions from detail; track manual ownership, errors and completed artifacts, not artificial % complete. |
| Review | `POST /jobs/:id/preview`, `/approve` `{gate, seenDigest,...}`; job detail + media | After PF-05/PF-02, proposed exact subject/revision/digest reference pinned for review, immutable evidence and history. Atomically compare grant subject and revision, require explicit principal, no fallback automation. Existing routes retain safeguards; never extend gate kinds from UI. |
| Import and attach | No universal Studio route | Proposed `POST /assets/import` with bounded stream, allowlisted media probing, local staging and rights fields; response artifact ID/hash/availability. Never accept arbitrary server paths or URL fetching from Studio. Attachment uses asset IDs; approval coverage requires PF-22. |
| Batch/campaign | `POST /queue` only enqueues one saved job | Proposed `POST /batches` (explicit collection of stable row IDs), `POST /batches/:id/validate`, `/submit`, `GET /batches/:id`; campaign defaults revision and rebase preview then explicit conditional commit. No partial write at validation. |
| Export | `GET/POST /jobs/:id/export` | Proposed `POST /exports/plans` with job revisions and preflight, `POST /exports` with plan ID/action keys. No overwrite default; check each again; result receipt with independent statuses. |
| Activity | Stage and queue logs and handoffs | No general agent launcher. Read-only artifact and run receipts until a separate scope and permission contract exists. |

Candidate response semantics: `422` invalid input by field/row; `409` stale revision/key collision/lock; `202` accepted plus stable receipt URI; `200` read/replay; `404` unknown resource; `503` missing runtime prereq or unavailable snapshot with remediation. Keep the existing error envelope where compatible; client adapter maps status+code, not English text. Batch request `{revision, rows:[{rowId,specRevision}], intentKey}`; persist one keyed receipt before writes and per-row outcomes/abort reasons; handle ambiguous crash by checking current job/queue records. `GET` must stay safe. Preserve local server origin/token protections; do not expose creds in receipts or actions via GET. Idempotency is proposed, not proven by the current UI lock.

**Assumptions:** compatibility remains the default, no schema deployment this phase. **Open questions:** maximum upload size, per-row key retention, replay exposure and conflicts on file-backed draft writes. [Domain](04-DOMAIN-MODEL.md) · [Roadmap](10-IMPLEMENTATION-ROADMAP.md).
