# 07 / Interaction design

**Research date:** 2026-11-24. **Scope:** state, keyboard, live updates and approval affordances. **Evidence / sources:** `contentos/ui/state.js`, `api.js`, `tests/browser/studio.spec.js`, [journeys](03-USER-JOURNEYS.md), [WCAG 2.2](https://www.w3.org/TR/WCAG22/). **Verified:** event refresh and named errors exist; fixture keyboard test checks dialog focus return. The following are proposed enhancements.

- Render canonical state from detail/API, not button clicks: draft → valid → queued/running → blocked/failed/rendered → QA eligible → exported. Gates can block before render; approval is not completion. States live on independent axes (execution, review, QA, export, readiness). Partial batch success is per-row, with an aggregate only after receipts exist.
- Mutation starts with explicit button and pending label. Disable submission while in flight; if it times out show “outcome unknown,” reread by job/receipt key before retry. SSE invalidates queries; disconnect shows last refresh plus poll/Retry. Preserve current row, scroll, filters, and selection on rerenders. Announce material changes via polite status only, not each tick.
- Creative review is advisory pending owner decision: `Not requested`, `Pending`, `Accepted`, `Changes requested`. Show independently of technical eligibility, QA and production grants. Export means local library copy only; no Publish action. If an owner later makes creative review blocking, bind it to the exact cut and rubric revision; a new cut invalidates it without altering the production grant.
- For fixtures or after R3 release criteria, the Approve dialog lists type, job/revision, exact subject + artifacts, current digest and diff link. Never replace an open digest after polling; mark stale, disable, and reopen review. On 409 re-fetch and discard intent. No key shortcut can grant approval, submit 20 jobs or overwrite exports. Current token is machine/session protection, not verified human attribution.
- Tab order follows reading order; skip navigation link first; route change focuses main heading, drawers/dialogs restore trigger. Native inputs, checkboxes, buttons. Tabs use RTL-aware arrows when true tab panels, links otherwise. Optional `/` focus search only when target is not editable and the shortcut can be disabled. Context menus use buttons and Escape; no hover-only labels or drag-only actions.
- Error messages state outcome, reason, recovery and stable code; hide secrets/absolute paths unless explicitly safe. Conflicts never resolve with silent overwrite. Sort/filter updates announce counts, not table HTML. Code/logs wrap by default and support explicit horizontal scroll with keyboard focus. Captions and transcript accessible without autoplay.
- Test 20-row import with mixed blockers, keyboard selecting filtered rows, theme switching with dialog open, stale digest, reconnect without duplicate action, retry symptoms, partial bulk export, and mobile magnification without obscured focus. Data fixture proves interaction only, not render.

**Assumptions:** no server-side draft autosave in first slice unless a conflict-aware save operation is built. **Open questions:** approval history retention and commenting policy.
